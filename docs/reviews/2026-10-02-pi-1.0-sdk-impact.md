# Pi 1.0.0 适配审查与子代理 SDK 底层改造影响

日期：2026-10-02（UTC）。审查基线：分支 `fix/pi-099-migration-2026-10-01`、HEAD `35f4edb` 及现有未提交工作树。本轮只修改报告、规划和续接；未升级正式依赖、修改业务 Runner 或重建 production dist。执行的是隔离兼容测试和模拟响应探针，不是 Pi 1.0.0 production/真实 Provider/TUI 认证。

> 后续实施：用户授权后已交付 Pi1.0/双后端，见 [实施验证报告](2026-10-02-dual-runtime-validation.md)。下文“未实施/下一候选”是保留的审查基线，不代表最新实现。

## 结论

1. **Pi 1.0.0 可以作为下一候选，不需要把现有功能整体重写。** 现有源码在隔离的四 Pi 1.0.0 / Host TypeBox 1.3.27 下完整 verify、独立 typecheck/build、主/子源码及隔离 built 入口 SDK 模拟测试通过。实际使用的 coding-agent 公共接口没有发现编译断裂。
2. **当前必须先解决版本绑定。** 磁盘全局 CLI 是 1.0.0，项目四 Pi dev 包仍为 0.99.2。加载未修改的本地 `pi-runtime.ts`，以实际全局 package bin 作输入，实测 `host_sdk_version_mismatch`。这是现有正确拒绝，不应删除 guard。磁盘/探针不能证明当前交互 Main 加载版本；昨日 0.99.2 同版验收仅属昨日候选。
3. **主要新增验收是 fullscreen；图像/codemode/MCP 按需接入，不自动给 child 增权。** 受限 child 当前关闭发现与 builtin，PowerShell/MCP 等未闭合能力仍准确拒绝。Main 用户配置的原生工具不等于 AgentFlux 已认证其全部 operation。
4. **Main 内独立 SDK session 是可行方向，但不能只替换 spawn。** 原生 1.0.0 模拟探针确认同一 PID 的两个会话可并发、独立 cwd/对话/工具上下文/费用，child dispose 后另一会话仍能请求；未验证真实 OAuth/Provider 并发、不合作工具取消或崩溃恢复。AgentFlux 仍使用进程后端。
5. **建议顺序：1.0.0 同版 production 候选 → Host SDK 唯一绑定 → 同一 Core Runner 的 SDK 适配 → 逐功能扩大。** 需要独立存活或进程级强制终止的 Run 保留进程后端；执行方式不是新的用户工作模式。

## 一、0.99.2 → 1.0.0 实际需要调整什么

### 版本与 API

- 全局 coding-agent 及其嵌套 pi-agent-core/pi-ai/pi-tui/pi-codemode/pi-mcp 实装 1.0.0；项目四 Pi 实装 0.99.2 / TypeBox 1.3.34。两个安装树不能以同版本声明代替模块身份。
- Node 最低要求仍 `>=22.19.0`，本机 Node 24.11.1；公开 coding-agent package exports、`bin.pi=dist/bundle/cli.js` 没有换入口。`client` 仍 source-only，不新增 compiled client 依赖。
- **低层导出并非完全不变**：pi-agent-core 根声明不再重导出基线中的大量 harness/telemetry/search 符号。AgentFlux 产品源码目前只直接依赖 coding-agent 公共 facade 和 TypeBox，所以隔离编译通过；未来 SDK 适配也应使用 facade，不能依赖旧 core 根导出或私有路径。
- 0.99.2 的 `ModelRuntime.generateImages` 已存在；1.0.0 新增的是 codemode 模型 helper 与公开 `ModelRegistry.generateImages` 接线，不能把整个底层 image API 误标成首次新增。

## 二、把子代理改为 Main 进程内 SDK：具体改哪些模块

### 目标形态（提案，不是已实现架构）

```text
flux_agent / Workflow planner,node,judge / Community 委派
  → 同一 Core runAgent：权限、预算、Run、消息、锁、终态
      → SDK driver：Main 内独立 AgentSession
      → process driver：需要独立生存/强制终止的 Pi Run
```

SDK driver 只处理 Host-bound session 构造、事件、输入、abort、资源释放；不拥有另一套 Task/Agent/Message/预算状态机。`Run.kind` 的持久/临时语义与 backend 正交；TUI background 是调用的呈现/等待方式，不是另一个 runtime。用户工具 schema 无需新增 backend/work-style 模式。

| 编号 | 现状源码 | 必需改造 | 若只替换 spawn 的具体风险 |
|---|---|---|---|
| S01 | `src/core/pi-runtime.ts`、`scripts/build.mjs`、`src/entry.ts` | 证明 Host SDK facade/module/ModelRuntime 注册表唯一绑定；冻结 Host 安装与本代 owner，SDK driver 不需要伪造 CLI invocation。保留进程 descriptor 与错版 guard；source/npm/bundled/SDK 安装分别验证。 | native ESM 仍可导入项目另一份 SDK；同进程不自动修复遮蔽，版本字符串相等也不证明唯一模块。不要借用 ModelRegistry 私有 runtime 或再 import 一份 Host 副本。 |
| S02 | `src/agents/agent-runner.ts`，目前 preflight/retry/spawn/JSONL/finalize 在同函数 | 提取共用 Run preflight、usage/budget、事件归并、终态与锁 finally；进程/SDK 只有 transport/driver 差异。新 SDK 执行通过 `createAgentSession`，不直接重写 Agent loop。 | 重复 runner 会让 planner/worker/judge 使用不同预算、状态和错误判据。进程实现保留严格 UTF8/LF，SDK 事件不能伪装 JSON frame。 |
| S03 | `src/subagent-entry.ts` 以 process.env 捕获身份/策略，message execute 再读 TASK_ID | 提供显式、不可变 RunIdentity/policy factory；CLI 仅作为 env 解码 wrapper，SDK 直接传参数。task/control/workspace/locks/startup IDs 均会话级，定时器按 Run 清理。 | 并发 child 共享或临时改 process.env 会串 sender、Task、权限及目录；factory 顶层/模块级状态与 pi.events 不因 session 独立自动隔离。不能为启动加全局 env 窗口。 |
| S04 | CLI `--no-extensions/skills/context-files/prompt-templates` 和显式安全入口 | 显式 cwd、settings、tools、独立 resourceLoader，只加载安全 factory 和有效 skills；保持 callable/nested gate。逐工具 env 以参数注入，禁 process.chdir。 | DefaultResourceLoader 默认发现扩展/MCP/上下文；只追加 safe factory 或 setActiveTools 不证明隔离。Main 控制入口不能作为 child factory 复用。SDK 不启用 builtin 不代表其他发现都关闭。 |

| S06 | `src/core/run-registry.ts` 运行中必须 pid，reconcile 依 dead PID | 同一 Registry 添加可版本化的 backend/逻辑 owner/attempt/session 描述；SDK 记录 owner Main PID+birth 和逻辑 Run generation，不能当独立 child PID。逻辑 handle 消失而 Main 存活也须可诊断/收敛，旧 process records 读取兼容且不回写。 | 把 Main PID 写成 child PID 会让 stop 杀 Main、所有 child liveness 相同、丢失 session 时无法回收。starting/no owner 仍不能由超时推导失败。 |
| S07 | `src/extension/rpc-inbox-pump.ts`、Message V2、`agent-run-control.ts` | 沿用唯一 Message V2 与同代 boundary receipt；SDK 用 session 输入队列，不新建 mailbox。queued/handled 不算消费；截止接受→drain→同代 settled→终态之间需要明确 fence，清监听前保留 ACK 依据。 | prompt Promise resolve 后可能另有独立 queued generation，立即 dispose/完成会丢 steer/follow-up 或误 ACK。失败/abort/unconsumed 仍保留或按目标 Run 拒绝，不跨 Run 污染。 |

| S10 | `src/core/active-context.ts`、`shared-board.ts`、`fs-lock.ts`、`lifecycle-gc.ts` | 保持既有 leaseId/runOwner；审计所有 releaseFileLock 无 owner 调用与逻辑 session cleanup。存储互斥仍保护外部进程，native file queue 不能替代。SDK owner 活着但 session 消失的残留需要逻辑 fence 与确已结束证据；仅缺 handle/心跳不授权清理，不按共享 PID 批量释放。 | 当前多数锁已用 `${agent}:${runId}`，不是全部要重写；但仅“进程活着保锁”会在 SDK handle 丢失时永久保留残留。不能按 Main PID 删除所有 child 锁。 |
| S11 | `src/workflows/dag-executor.ts`、`quality-gate.ts`、checkpoint | planner、node、judge 仍调用同一 runner；传内部 Host/backend context。依赖/并发/质量判定和 checkpoint 保留；失败/取消与晚到事件定向收敛。 | 不能只迁移 flux_agent；否则 Workflow/judge 仍 spawn 或恢复口径不一。judge 模型成功不等于 verdict pass。 |

### 对现有功能的影响

- **可以保留外部行为但必须回归**：Agent create/多角色/run/retry/inspect、shared/fresh/fork/last(k)、Task new/continue/reuse/resume/retry 谱系、Workflow 并行/quality gate/checkpoint、Community Claim/Review、Message V2 direct/group/busy-follow-up、费用与父预算。SDK 不要求废弃这些功能，也不允许用 Promise 的完成代替 Core 完成。
- **会改变保证或事实的部分**：Main 内后台任务随 Main 崩溃一起消失；独立 Pi 的进程强制终止/故障域不再存在；PID/启动遥测变为 Host owner + SDK logical session。恢复必须新 Task/Execution/Run，从持久 checkpoint/session 派生，不能声称 SDK 内存 handle 在重启后继续。
- **不会自动得到的能力**：权限沙箱、真实 Provider并发可靠性、macOS支持、Bun/installer支持、工具进程清理、OAuth刷新协调、性能保证。shell/MCP 本身仍可能启动系统进程；“不再每 Run spawn Pi CLI”不是“零子进程”。
- **预期收益尚需测量**：去掉 Pi CLI boot/JSONL 往返与每 Run 一份运行时；可受控继承 Host provider/认证实现。模型请求/Token 数不因此减少，内存会话也不等于不收费；长期多会话反而需要 dispose/泄漏/背压测试。

### 建议实施分批与验收（详细状态只见 COMPAT-22/23）

1. 独立验收 1.0.0 同版 production：错版拒绝、fresh Main/child、八类现有功能、费用、包资产；补 regular/fullscreen 人工验收，不同时切后端。
2. Host facade 与 explicit safe factory 先行，写逻辑 owner/schema 架构；用同一 Core runner 分离 process driver，不改公共工具动作或历史记录。
3. SDK 先受控验证 planner/reviewer/judge 等范围，再扩大 persistent Agent 和并行节点；不是按角色名字永久判安全。写操作/技能/长工具仍按能力与取消要求选择，未认证 driver 不静默接管全部任务。
4. 真实同 Provider 并发、child 后 Main 再请求、abort/retry/OAuth刷新、嵌套权限、不同 cwd/resource 污染、Message V2同代 ACK、.73费用与继承不重收、同父预算、session replacement/reload、Main崩溃/SDK handle丢失、锁/GC、不合作工具与进程后端回退全部有正负证据。适配后重新跑八类 fresh；当前 0.99.2 认证不顺延。

## 三、本轮验证与限制

证据目录：`.agentflux/test-results/pi-1.0-audit-2026-10-02/`。

- `baseline.json`：176 产品文件及 production entry/subentry/preload 指纹，真实全局嵌套包与本地依赖路径。`fixture-links.json`：独立复制代码，junction 指向 Host 1.0.0 四包/TypeBox，其余复用原依赖；只改隔离 manifest。
- `isolated-gates-1.0.json`：runtime 单测、主/子 SDK 模拟、完整 `npm run verify`、独立 `npm run typecheck`、`npm run build` 均 exit=0。
- `isolated-extra-gates-1.0.json`：两个隔离 built 主/子入口模拟与 SDK feasibility 均 exit=0。费用 .73、model-only 拒绝、nested/path/PowerShell 毒丸零执行、结构化协议与 receipt 保留。
- `sdk-feasibility-probe.json`：原本地 0.99.2 模块对全局1.0.0 bin 的错版拒绝；原生 fullscreen/regular/header 设置；同 PID 两会话 mock 请求重叠、cwd/session/历史/费用分开、不修改共享 env/cwd、child dispose 后另一会话继续。
